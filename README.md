# feeda

サーバー負荷を最小にしたRSSリーダー。フィード本文はブラウザのIndexedDBにのみ保存し、サーバー（Flask + Neon）が扱うのは暗号化済みの「購読リスト」だけです。サーバー側はシードを保存しないため、購読データを復号できません。バックグラウンドでのフィード巡回も行わず、フィード一覧をクリックした時にだけその場でフィードを取得します。

構成:


- `backend/` — Flask API（`/api/sync`, `/api/fetch-feed`）。Neon Postgresに暗号化ブロブを保存するだけで、フィード内容は保存・パースしません。
- `public/` — 3ペイン（フィード一覧 / 記事一覧 / プレビュー）のRSSリーダー本体。素のHTML/CSS/JS、ビルド不要。Vercelの静的ファイル配信規約に合わせて`public/`という名前にしています。
- `userscript/` — Tampermonkeyスクリプト。閲覧中のページからRSS/Atomフィードを検出し、未登録のものだけ購読リストに自動追加します。OPMLファイルからの一括インポートにも対応。
- `api/index.py`, `vercel.json` — リポジトリ全体を1つのVercelプロジェクトとしてデプロイするためのエントリポイント（Webアプリの静的配信とFlask APIを同一ドメインで提供）。

## 1. Neonのセットアップ

1. [Neon](https://neon.tech)でプロジェクトを作成し、接続文字列（`postgresql://...`）を控える。Vercelの「Storage」タブからNeon連携を追加した場合は、この手順は不要です（`DATABASE_URL`/`POSTGRES_URL`が自動で設定されます。下記参照）。
2. テーブルは初回のAPIリクエスト時に自動作成されるので、手動でのマイグレーションは不要。

## 2. バックエンド（Flask）をローカルで動かす

リポジトリのルートで実行します（`requirements.txt`はルート直下にあります）。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp backend/.env.example backend/.env
# backend/.env の NEON_DATABASE_URL を実際の接続文字列に、ALLOWED_ORIGIN をWebアプリのオリジンに書き換える
python backend/app.py
```

`http://localhost:5000/api/healthz` が `{"status": "ok"}` を返せば起動成功です。

## 3. Vercelへのデプロイ（Webアプリ + APIを1プロジェクトで）

このリポジトリは**リポジトリのルートをそのままVercelプロジェクトのRoot Directoryとして**デプロイする構成になっています。WebアプリとFlask APIが同一ドメイン・同一デプロイで公開されます。

- `vercel.json` は明示的な`builds`/`routes`形式（Flask公式ガイドと同じ、いわゆるBuild Output API v1形式）を使っています。`rewrites`（新しいZero-Config向けの書き方）はWSGIアプリへのキャッチオールでは実際のリクエストパスがFlask側に渡らず、全ルートが404になる問題があったため使っていません。
  - `api/index.py`（`backend/`のFlaskアプリをラップしたエントリポイント）が`@vercel/python`でビルドされ、`/api/*`宛のリクエストはすべてそこにルーティングされます（元のパスがそのままFlaskに渡ります）。
  - `public/**`が`@vercel/static`でビルドされ、それ以外のリクエストは静的ファイルとして配信されます。
- `requirements.txt` はルート直下に置いてあります（Vercelのビルドがここから依存関係を検出します）。
- **データベース接続文字列の環境変数名は`NEON_DATABASE_URL`・`DATABASE_URL`・`POSTGRES_URL`のいずれでも構いません**（この順で探します）。VercelのStorageタブからNeon連携を追加した場合は`DATABASE_URL`/`POSTGRES_URL`が自動設定されるので、追加の設定は不要です。手動でNeonプロジェクトを作った場合はEnvironment Variablesに`NEON_DATABASE_URL`を追加してください。
  - **環境変数の追加・変更は既存のデプロイには反映されません。** 保存後、Deployments画面から最新デプロイを選び「Redeploy」するか、`git push`等で新しいデプロイをトリガーしてください。
- `ALLOWED_ORIGIN` は同一ドメイン配信なら省略可（Webアプリからのfetchは同一オリジンになるためCORSは実質不要）。別ドメインからAPIを叩く場合のみそのオリジンを設定してください。
- フィード取得プロキシ（`/api/fetch-feed`）は対象URLをクエリ文字列ではなく `X-Feed-Url` ヘッダーで受け取ります。これはVercelのリライトを経由すると、クエリ文字列中のスラッシュがエンコードされて元のURLと食い違うことがあるための対策です。
- DB接続に必要な環境変数が無い場合でも`/api/healthz`のようなDBを使わないルートは正常に応答します（データベースへの接続はモジュールのimport時ではなく、実際にDBが必要なリクエストが来たときに初めて行う設計になっているため、設定漏れがサイト全体を巻き込んで落とすことはありません）。

## 4. Webアプリを開く

上記のVercelデプロイ後、そのURL（例: `https://your-app.vercel.app`）を開きます。ローカルでWebアプリだけを動かしたい場合は`public/`を`python -m http.server`等で配信してください。

初回起動時にセットアップ画面が表示されます。

- 新規に始める場合は「新しいシードを生成」を押し、表示されたシードを安全な場所に保管してください（**シードを失うと同期データには二度とアクセスできません**）。
- 別端末で既に使っている場合は、そのシードを貼り付けてください。手入力の代わりに、セットアップ画面下部の「QRコードを読み取る」「6桁コードで受け取る」から別端末のシードをそのまま引き継ぐこともできます（後述）。
- 「APIベースURL」は、手順3のように**WebアプリとAPIを同一ドメインでデプロイしている場合は空欄のまま**で構いません（同一オリジンへの相対パスでアクセスします）。ドメインが別の場合のみ、APIのURL（例: `https://your-app.vercel.app`）を入力してください。

### シードの引き継ぎ（QRコード / 6桁コード）

セットアップ済みの端末で画面右上の「シード」→「QRコードで共有」または「6桁コードで共有」を開くと、別端末（またはTampermonkeyスクリプト）にそのままシードを引き継げます。シードの文字列を手でコピー＆ペーストする必要はありません。

- **QRコード**: シードとAPIベースURLをその場でQRコードにエンコードして表示するだけで、サーバーには一切送信されません。別端末のセットアップ画面で「QRコードを読み取る」を開き、カメラで読み取ると設定欄に自動入力されます（内容を確認して「開始」を押してください）。
- **6桁コード**: サーバー上に暗号化した状態で一時的に保管し、6桁の数字コードで受け渡します。コードは3時間で失効し、一度受け取ると即座に無効化される使い捨てです（サーバー自体はコードの中身を復号できません）。別端末のセットアップ画面またはTampermonkeyのメニューから「6桁コードで受け取る」を選び、表示されたコードを入力してください。「6桁コードで共有」を開き直して新しいコードを発行すると、直前に発行したコードはその場で無効化されます（3時間有効なので、古いコードを共有相手以外が拾える状態のまま放置しないためです）。

どちらの画面も、他人に見せると同じ同期データにアクセスされてしまう点はシードそのものと同じです。

### 一時的にRSSリーダーを見せる（一時URLで共有）

シード自体を教えることなく、他人に一時的に「私のRSSリーダー」を見せたい（同じ端末を貸す、画面共有中に一時的に操作を任せる、など）場合は、「シード」→「一時URLで共有」から一回限りのURLを発行できます。

- 生成されたURLを開いた人は、シードを見ることなく通常時と同じ権限（一時停止操作なども含む）でアクセスできます。
- URLは3時間で失効し、一度開かれると即座に無効化される使い捨てです（サーバー上に保管された期限付きの暗号化ブロブを、URLの`#`以降にしか含まれないランダムな鍵で復号する仕組みのため、サーバー自身も内容を復号できません）。
- 「一時URLで共有」を開き直して新しいURLを発行すると、直前に発行したURLはその場で無効化されます（3時間有効なので、古いURLを共有相手以外が拾える状態のまま放置しないためです）。
- 受け取った側の端末では、シードは（通常のセットアップのようにブラウザに保存され続けるのではなく）そのタブを開いている間だけ保持されます。**タブを閉じると、その端末からは二度とアクセスできなくなります**。受け取った側の画面には「シード」ボタン自体が表示されず、シードの値を見たりコピーしたりすることはできません。
- 同じ端末で普段使っているセッションとIndexedDBを共有するため、それまでにその端末で一度でも開いたことのあるフィードはそのまま見えます（フィードの巡回自体はフィード一覧をクリックした時にだけ行われる仕組みのため、リンクを開いた側から新たに何かを取得しに行くようなことはありません）。
- リンクを発行した側の通常のセッションには何の影響もありません。



feedaはPWA（インストール可能なWebアプリ）にも対応しています。デスクトップ/モバイル問わずブラウザのアドレスバーやメニューから「インストール」するとホーム画面・アプリ一覧にアイコンが追加され、単独のウィンドウで起動できます。`sw.js`はCSS/JS/アイコンなどの静的ファイルを常にネットワークから優先的に取得し（`/api/`宛のリクエスト＝フィード取得・同期は元から対象外で、常にネットワークへ直接アクセスします）、オフライン時や取得に失敗した場合だけキャッシュにフォールバックします。ネットワーク優先にしているのは、キャッシュ優先だとインストール済みの環境にアプリの更新が届かなくなる（＝古いバージョンのまま固定される）ためです。

## 5. Tampermonkeyスクリプトのインストール

1. ブラウザにTampermonkey拡張機能をインストール。
2. `userscript/feeda-autoregister.user.js` の内容をTampermonkeyの新規スクリプトとして貼り付けて保存。
3. シードとAPIベースURLを設定する方法は3通りあります。
   - **自動引き継ぎ**: 同じブラウザで既にWebアプリ（例: `https://feeda-two.vercel.app/`）をセットアップ済みなら、そのページを開くだけで（ページ内に保存済みのシードを検出し）自動的に設定されます。何もする必要はありません。
   - **6桁コード**: Tampermonkeyアイコン →「feeda: 6桁コードでシードを取得」を選び、Webアプリの「シード」→「6桁コードで共有」で表示されたコードを入力します。
   - **手動設定**: Tampermonkeyアイコン →「feeda: シードとAPIを設定」を選び、Webアプリで使っているシードと同じシード、およびAPIベースURLを直接貼り付けます。
4. 以後、RSS/Atomフィードを持つサイトを開くと、そのページに未登録のフィードがあれば自動的に購読リストへ登録されます（初回、ブラウザからAPIドメインへのアクセス許可を尋ねられる場合があります）。

登録済みのフィードには反応しないよう、フィードIDのローカルキャッシュを6時間ごとにサーバーと突き合わせて更新します。

APIベースURLを省略した場合（自動引き継ぎ・6桁コードのいずれでも設定できなかった場合）は、メンテナ自身の本番デプロイ先 `https://feeda-two.vercel.app` がデフォルトとして使われます。自分で別ドメインにデプロイしている場合は、手動設定からそのURLを入力し直してください。

### OPMLの一括インポート

他のRSSリーダーからの乗り換え用に、Tampermonkeyアイコン →「feeda: OPMLをインポート」からOPMLファイルを選択すると、ファイル内の全フィードのうち未登録のものだけをまとめて購読リストに追加できます（登録済みのものは自動的にスキップされます）。

## Webアプリの操作

- フィードの追加・削除はWebアプリ側では行いません。Tampermonkeyスクリプトの自動登録またはOPMLインポートだけがフィードの登録手段です。
- 常に3ペイン構成です：左がフィード一覧、中央が選択中のフィードの記事一覧、右がプレビューです。フィード一覧は画面幅にかかわらず常に表示されます。
- **バックグラウンドでのフィード巡回は行いません。** フィード一覧から1件クリックしたときにだけ、そのフィードをその場で取得します（既にキャッシュされている記事はクリック直後に即座に表示され、取得が終わり次第、新着があれば追加されます）。ページを開いただけでは何も取得されません。
- 既読/未読は管理していません。フィードを選択すると、そのフィードのキャッシュ済み記事が新着順にすべて表示されます（既読・未読の区別や自動的な絞り込みはありません）。
- フィード一覧はピン留めしたフィードが先頭、次に購読中のフィードが投稿頻度（1日20回以上→…→週数回→週1回程度→月1回程度→それ以下→頻度不明の順、各グループ内は五十音順）ごとにグループ分けされ、最後に更新停止中のフィードがまとまります。投稿頻度は一度でも取得したフィードの記事の投稿日時から自動的に判定され（未取得のフィードは「頻度不明」）、他フィールドと同様に暗号化して同期されるので、まだ取得していない端末でもグループ分けだけは反映されます。フィード名にマウスホバーすると、色タグ・ピン留め・更新の一時停止／再開・URLコピーのアイコンがその場に表示されます。
- 記事一覧の行をクリックすると、右のプレビューペインにその記事が表示されます。プレビュー内のリンクから元サイトを新しいタブで開けます。
- 記事一覧の行にマウスホバーすると、色タグを付けるパレットとコメント欄がその場に表示されます（右クリックや長押しは不要です）。色を付けた記事・コメントした記事は左ボーダー＋薄い背景色で示され、直近のコメントは通常時も1行プレビューされます。プレビューペイン自体には色付け・コメント操作はありません（記事一覧側で行ってください）。
- キーボードショートカットがあります（画面右上「⋯」→「キーボードショートカット」、または `?` キーでいつでも一覧表示）。`j`/`k`（または上下矢印）で記事一覧内のフォーカスを移動、`Enter`/`o` でフォーカス中の記事をプレビューに表示、`u` で検索をクリア、`/` で検索欄にフォーカス、`r` で見る／振り返るを切り替えられます（入力欄にフォーカスがある間は無効になります）。
- ペイン境界をドラッグして幅を調整できます（幅はブラウザに記憶されます）。
- 画面右上の「⋯」ボタンから「NGワード」「URLブロック」「シード」「キーボードショートカット」「OPMLをエクスポート」を開けます。「振り返る」（📖）はよく使うため引き続き常設のアイコンボタンです。
- 「OPMLをエクスポート」は、現在購読中のフィード（一時停止中も含む）を標準的なOPML 2.0形式でダウンロードします。他のRSSリーダーへの乗り換えやバックアップに使えます。
- 振り返る画面の日付ナビ右にある「⬇️」ボタンから、記録（開いた・コメントした・色を付けた記事の履歴）全件を1つのJSONファイルとしてダウンロードできます。特定の日で絞らず、常に全期間分がまとまって出力されます。
- カラーパレットによるフィード絞り込み（色タグを付けたフィードがある場合のみ表示）は、検索履歴バーと同じ行の左側に配置されています。
- 検索欄に入力すると、それまでにこの端末で一度でも取得したことのある（＝IndexedDBにキャッシュされている）記事全体からフィード名・タイトル・本文を横断検索します。まだ一度もクリックしていないフィードの記事は検索対象になりません。検索でヒットした文字列は記事一覧・プレビュー内で黄色背景＋太字にハイライトされます。
- フィード取得中は画面最下部に進捗をプログレスバーで表示します（取得が無い時は表示されません）。
- フィード名をクリックして開く操作から、そのフィードの取得を一時停止／再開できます。一時停止中のフィードは一覧の「更新停止」グループに移動しますが、既存のキャッシュ済み記事はそのまま残り、選択すればいつでも表示できます（取得だけが行われなくなります）。この状態は他フィールドと同様に暗号化して同期されます。
- フィード名を中クリックすると、そのフィードのURLをクリップボードにコピーします。
- 登録しているフィードの総数は、検索ボックスのプレースホルダー（「N件を検索・URLを貼り付けて登録」）に表示されます。同じ場所にURL貼り付けでの登録方法も添えています。
- 画面右上の「⋯」→「シード」から、現在使用中のシードとAPIベースURLをいつでも確認・コピーできます（セットアップ済みの環境ではセットアップ画面が出ないため、別端末やTampermonkeyスクリプトに同じシードを設定したいときはここから参照します）。

## セキュリティ上のメモ

- `/api/fetch-feed` はSSRF対策として、対象ホストを名前解決した実IPがプライベート/ループバック/リンクローカル等でないか検証してから取得します。
- 記事本文はプレビュー表示前にタグ・属性のアローリストでサニタイズしており、`<script>`等は描画されません。
- シード引き継ぎ用の`/api/pair/<code>`はアカウントIDによる認証を持ちません（そもそもアカウントを持たない端末にシードを渡すための仕組みのため）。6桁コード（100万通り）自体の総当たりを、有効期限（3時間）・一度使うと即失効する使い捨て設計・厳しめのレート制限（`RATE_LIMIT_PAIR_READ`）の3つで防いでいますが、完全に不可能にするものではありません。個人〜小規模利用を前提にした設計判断です。有効期限を数分から3時間に延ばした分、新しいコードを発行するたびに直前のコードを明示的に無効化する（`DELETE /api/pair/<code>`）ようにして、有効なコードが同時に複数出回ったままにならないようにしています。
- 一時URL共有用の`/api/share-link/<id>`も同様に認証を持ちません。`<id>`はクライアントが生成する128bitのランダム値（総当たりは非現実的）で、復号に必要な鍵はURLの`#`以降（フラグメント）にしか含まれずサーバーには一切送信されないため、サーバー上のデータが漏れても内容は復号できません。有効期限（`SHARE_LINK_TTL_SECONDS`、3時間）と一度使うと即失効する使い捨て設計は6桁コードと同様です。新しいリンクを発行するたびに直前のリンクを明示的に無効化する（`DELETE /api/share-link/<id>`）点も6桁コードと同じです。
